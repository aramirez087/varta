## Known limitations — explicitly NOT included in v0.1.0

These are deliberate roadmap deferrals; v0.1.0 ships without them and the
README/handoffs document the rationale.

- **`no_std` support.** `varta-vlp` is `no_std`-friendly (`std::error::Error`
  impls are behind the opt-in `std` feature),
  but `varta-client` and `varta-watch` depend on `std` for `UnixDatagram`,
  `Instant`, and `HashMap`. A `no_std`-compatible split is a v0.2 conversation.
- **Visual CLI dashboard.** `varta-watch` ships a Prometheus `/metrics`
  endpoint and a tab-separated file exporter; a TTY-rendered live dashboard
  is roadmapped for v0.2.
- **eBPF-based observer.** v0.1.0 uses Unix Domain Sockets exclusively. An
  eBPF/ring-buffer transport (kernel-side capture without per-process
  coordination) is a v0.3 line item.
- **Multi-OS CI / Windows support.** CI runs on `ubuntu-latest` only.
  Production code targets Unix; macOS works but is verified locally only.
  Windows is unsupported in v0.1.0.
- **SIGINT handler in `varta-watch` daemon.** Per Session 05's open issue
  R10, std-only signal install requires a non-trivial libc shim. The daemon
  shuts down on `--shutdown-after-secs` only; `SHUTDOWN: AtomicBool` is
  pre-wired so a future v0.1.x can flip it from a hook.
- **`varta-watch --prom-addr` startup banner.** Per Session 06's open issue
  D-S05-banner, the daemon does not print the bound port; consumers use a
  TOCTOU probe-port pattern. Trivial v0.1.x follow-up.
- **`io::ErrorKind::Other` (ENOBUFS) in `BeatOutcome::Dropped`.** Per
  Session 06's open issue D-ENOBUFS, the macOS kernel surfaces ENOBUFS as
  `ErrorKind::Other`, which the client maps to `Failed(_)`. Trivial v0.1.x
  one-line widen at `crates/varta-client/src/client.rs:104`.
