## 3. Wire formats (frozen this session)

### `FileExporter` line schema (one event per line, `\n`-terminated)

```
<observer_ns>\t<kind>\t<pid>\t<nonce>\t<status>\t<payload>\n
```

- `kind ∈ {beat, stall, decode, io}`.
- For `decode`/`io` events `pid`/`nonce`/`status`/`payload` are `-`.
- `status` is the lowercase debug name (`ok|degraded|critical|stall`).
- `observer_ns` is sourced from a process-local `Instant::now()` delta the
  exporter holds — the `Event` enum does not carry a per-event timestamp,
  so each `record()` snapshots its own. Documented in module rustdoc.
- The acceptance test only asserts `lines.count() == N`, but a stable schema
  is mandated by the contract (`stable schema`).

### `PromExporter` HTTP/Prometheus framing

Response (single buffer, written in one `write_all`):

```
HTTP/1.0 200 OK\r\n
Content-Type: text/plain; version=0.0.4\r\n
Content-Length: <N>\r\n
Connection: close\r\n
\r\n
<body>
```

Body (regex-stable):

```
# HELP varta_beats_total Total accepted beats per agent pid.
# TYPE varta_beats_total counter
varta_beats_total{pid="<P>"} <N>
# HELP varta_stalls_total Total observer-detected stalls per agent pid.
# TYPE varta_stalls_total counter
varta_stalls_total{pid="<P>"} <M>
# HELP varta_status Last reported status code per agent pid (0=ok,1=degraded,2=critical,3=stall).
# TYPE varta_status gauge
varta_status{pid="<P>"} <S>
```

Pids are emitted in numerically sorted order so output is deterministic.
Tests grep with `varta_beats_total\{pid="...."\} N` style assertions —
no third-party regex crate; we use `str::contains` and split-based scans.

## 4. Design decisions and rationale

### D1 — `Recovery` uses `HashMap<u32, Instant>` for debounce state
Per the prompt: "HashMap is fine (cold path)". Recovery fires only on
stalls; allocation on stall is acceptable. Using `Tracker`-style fixed
arrays would couple the recovery layer to tracker capacity unnecessarily.

### D2 — `Recovery::on_stall` returns an enum, not `Result`
`Debounced` and `SpawnFailed(_)` are both expected runtime outcomes; the
caller (the daemon main loop) records each into the exporter without
treating either as fatal. Using `Result` would conflate the spawn failure
with the policy-gated debounce.

### D3 — `{pid}` substitution is literal `replace`, no escaping
The shell is `/bin/sh -c <rendered>`, so the user-supplied template owns
quoting. Documenting `{pid}` as the only substitution token in HELP
prevents future feature creep into a templating language.

### D4 — Exporter framing is a trait, but the daemon owns concrete instances
`Box<dyn Exporter>` would heap-allocate once at startup; that is acceptable
because `connect()`/heap rules apply to the client, not the observer. We
still prefer `Option<FileExporter>` + `Option<PromExporter>` in `main` so
each gets its own concrete type and `serve_pending()` (Prom-only) does not
need to leak through the trait.

### D5 — `PromExporter` is poll-driven, not threaded
`serve_pending()` accepts every ready connection on the nonblocking
listener and writes a fresh metrics body per connection. The daemon calls
it once per outer loop iteration. No background thread, no shared state,
no `Mutex`. Tests connect synchronously after sending data, then call
`serve_pending()` from the test thread before reading — see §6 below.

### D6 — `PromExporter` reads the full HTTP request before responding
The acceptance tests send a real `GET /metrics HTTP/1.0\r\n\r\n`. The
exporter reads until it sees `\r\n\r\n` (or 4 KiB cap, whichever first),
discards the request line, and unconditionally responds with 200 +
metrics. We do not parse the path: `/metrics` is the only endpoint and
asserting exactly that requires no extra logic the test would touch.

### D7 — Counter aggregation lives inside `PromExporter`
`PromExporter::record` increments per-pid `beats_total` / `stalls_total`
and updates `last_status` directly. `FileExporter::record` only writes a
line — it does not aggregate. This separation matches the test contract
(file → "one line per event"; prom → "totals").

### D8 — `Config::from_args` is hand-rolled, GNU-style long flags only
- `--socket <path>` (required)
- `--threshold-ms <u64>` (required)
- `--recovery-cmd <template>` (optional)
- `--recovery-debounce-ms <u64>` (default `1000` if `--recovery-cmd` set)
- `--export-file <path>` (optional)
- `--prom-addr <ip:port>` (optional, parsed via `str::parse::<SocketAddr>`)
- `--shutdown-after-secs <u64>` (optional, used by tests)
- `--help` / `-h` → returns `Err(ConfigError::HelpRequested)`; `main`
  prints `Config::HELP` to stdout and exits 0. (Stdout from the binary is
  fine — `clippy::print_stdout` is forbidden in the lib by the lint, but
  applies via `#![forbid(...)]` only where declared. The binary uses
  `eprintln!` for errors and `std::io::Write` on `stdout()` for `--help`,
  not the `print*` macros.)

> Note on `print_stdout`: the rule applies wherever `#![forbid(...)]` is
> declared. We must not use the `println!` macro in the binary either,
> since the rule's spirit is "no banner prints, route diagnostics through
> stderr." `--help` writes via `std::io::stdout().write_all(...)` which
> the lint does not flag.

### D9 — Daemon shutdown
`main.rs` installs a `static SHUTDOWN: AtomicBool = AtomicBool::new(false);`
and registers a SIGINT handler via `std::os::unix::*` only if available
in std without extra deps. **If std-only signal install proves unviable,
fall back to deadline-only shutdown (`--shutdown-after-secs`) and
document.** Tests use `--shutdown-after-secs` exclusively, so SIGINT is a
"nice to have" gated behind std availability.

> Concrete fallback: `std::os::unix::raw::*` does not include
> `signal()`. Without `libc`, the only std-supported way to install a
> signal handler is `std::process::abort_unsoundness_TBD` — i.e., none.
> Decision: ship deadline-only shutdown for v0.1.0. The handoff records
> this as an open issue for v0.2; SIGINT is not in any S05 acceptance
> test. The static `AtomicBool` is wired so a future signal hook can
> flip it.

### D10 — Test isolation for `prom_exporter_*`
Tests bind to `127.0.0.1:0`, then call `local_addr()` to discover the
port. No fixed-port collisions, no `#[serial]`. The TCP socket is closed
when the test's `PromExporter` drops.

### D11 — Test isolation for `recovery_cmd_*`
Each test mints a unique tempfile path under `std::env::temp_dir()` using
a process-pid + atomic-counter combo (mirrors the Session 03 helper). A
small RAII `TempPath` guard removes the marker/log file on drop.

### D12 — `cli_smoke.rs` uses `env!("CARGO_BIN_EXE_varta-watch")`
Cargo provides this env var to integration tests targeting the same crate
as a binary. No `target/debug/...` path-mangling, no Cargo invocation
reentrancy. Test spawns with `Command::new(env!("CARGO_BIN_EXE_varta-watch"))
.arg("--help").output()` and asserts every documented flag substring is
present in `stdout`.

### D13 — `Event` is `Debug` only — we cannot pattern-match on it as `Copy`
`Event::Decode` carries a `DecodeError` (Copy) and `Event::Io` carries a
`std::io::Error` (NOT Copy). Exporters take `&Event`, never own one.

### D14 — `FileExporter::record` formatting via `write!` to a `BufWriter`
`std::io::BufWriter<File>` is a stdlib facility, no extra deps. `flush()`
forwards to the underlying writer. The trait surface accepts `&mut self`
so each exporter owns its own write strategy.

### D15 — `PromExporter` `\n`-vs-`\r\n` body lines
Prometheus text format expects `\n`. The HTTP framing uses `\r\n` for
headers but the body is plain text with `\n` line terminators. Tests grep
on the body, not headers — no ambiguity if we emit `\n` consistently for
metric lines.

## 5. Test design (RED phase contracts)

### `tests/recovery_e2e.rs`

```rust
#[test]
fn recovery_cmd_fires_once_per_stall_within_debounce() {
    let marker = unique_tmp("marker");
    let template = format!("touch {}", marker.display());
    let mut rec = Recovery::new(template, Duration::from_secs(1));
    // Two firings within 500ms should produce 1 actual file creation.
    let first  = rec.on_stall(42);
    let second = rec.on_stall(42);
    assert!(matches!(first,  RecoveryOutcome::Spawned(s) if s.success()));
    assert!(matches!(second, RecoveryOutcome::Debounced));
    assert!(marker.exists());
    // Re-running the test asserts marker created exactly once: count
    // creations by listing the parent dir filtered to our suffix.
    // (Simpler: pre-delete, then assert exists() && metadata == 1 entry.)
}

#[test]
fn recovery_cmd_template_substitutes_pid() {
    let log = unique_tmp("log");
    let template = format!("echo $$:{{pid}} >> {}", log.display());
    let mut rec = Recovery::new(template, Duration::from_secs(0));
    let outcome = rec.on_stall(12345);
    assert!(matches!(outcome, RecoveryOutcome::Spawned(s) if s.success()));
    let body = std::fs::read_to_string(&log).expect("log content");
    assert!(body.trim_end().ends_with(":12345"),
            "log line did not end with pid: {body:?}");
}
```

Notes:
- The first test's "exactly once" is enforced by `Spawned` then
  `Debounced` plus `marker.exists()` — `touch` is idempotent, so we
  cannot count creations from the marker alone. Acceptable: the
  `Debounced` outcome is the proof of "did not invoke the shell twice."
- `unique_tmp(tag)` mirrors `acceptance.rs::unique_uds_path` — copied
  inline (test-only helper, no cross-test sharing required).

### `tests/exporter_endpoint.rs`

```rust
#[test]
fn prom_exporter_reports_beats_total_per_pid() {
    let mut prom = PromExporter::bind("127.0.0.1:0".parse().unwrap()).unwrap();
    let addr = prom.local_addr().unwrap();

#[test]
fn prom_exporter_reports_stalls_total_per_pid() {
    let mut prom = PromExporter::bind("127.0.0.1:0".parse().unwrap()).unwrap();
    let addr = prom.local_addr().unwrap();
    prom.record(&Event::Beat  { pid: 9, status: Status::Ok, nonce: 1, payload: 0 });
    prom.record(&Event::Stall { pid: 9, last_nonce: 1, last_ns: 0 });
    let body = http_get(addr, "/metrics");
    assert!(body.contains(r#"varta_stalls_total{pid="9"} 1"#),
            "missing stalls_total counter:\n{body}");
}

#[test]
fn file_exporter_appends_one_line_per_event() {
    let path = unique_tmp("export");
    let mut fe = FileExporter::create(&path).unwrap();
    let events = [
        Event::Beat  { pid: 1, status: Status::Ok,       nonce: 1, payload: 0 },
        Event::Beat  { pid: 1, status: Status::Degraded, nonce: 2, payload: 0 },
        Event::Stall { pid: 1, last_nonce: 2, last_ns: 0 },
        Event::Decode(DecodeError::BadMagic),
    ];
    for ev in &events { fe.record(ev); }
    fe.flush().unwrap();
    let body = std::fs::read_to_string(&path).unwrap();
    assert_eq!(body.lines().count(), events.len(),
               "file exporter line count mismatch:\n{body}");
}

fn http_get(addr: SocketAddr, path: &str) -> String {
    use std::io::{Read, Write};
    use std::net::TcpStream;
    // Test helper drives PromExporter::serve_pending in a small loop on a
    // background thread so the connect/write/read race resolves
    // deterministically. Loop runs ≤500ms.
    ...
}
```

Notes:
- `http_get` test helper: spawns a thread that calls `prom.serve_pending()`
  in a tight loop with `thread::sleep(1ms)`. **Wait — `prom` is owned by
  the test thread.** Approach: take a `&mut PromExporter` and drive
  `serve_pending` from the test thread BETWEEN `connect()` and
  `read_to_end()`. Concretely:
  1. `let stream = TcpStream::connect(addr)?` (nonblocking-on-listener
     means accept happens on next poll — connect itself succeeds because
     the kernel buffers the SYN/ACK).
  2. `stream.write_all(b"GET /metrics HTTP/1.0\r\n\r\n")?`
  3. Loop: `prom.serve_pending()?` then `thread::yield_now()` until the
     stream is readable (deadline 500ms).
  4. `stream.read_to_end(&mut buf)?` to drain the response.

  This keeps everything single-threaded.

## 6. Risks and mitigations

| # | Risk | Mitigation |
|---|---|---|
| R1 | "Empty `[dependencies]`" rule is literally violated by the existing path-dep on `varta-vlp`. | Already accepted in Session 03 handoff; do not re-litigate. Plan does not add new deps. Carry the open issue forward verbatim. |
| R2 | `Recovery::on_stall` runs `/bin/sh -c` synchronously and could block the daemon poll loop. | Document explicitly as cold-path tradeoff. Use `Command::status()` not `output()` so we don't buffer stdout/stderr in memory; recovery scripts redirect themselves. v0.2 may move to spawn+wait-async. |
| R3 | `PromExporter` could be DoS'd by a hung client. | Each accepted connection sets a 1s read+write timeout on the resulting `TcpStream`. After write, drop the stream (HTTP/1.0 + `Connection: close`). |
| R4 | Test flakiness around `serve_pending` polling timing. | Synchronous helper drives `serve_pending` from the test thread before reading from the connected `TcpStream`; bounded retry with 500ms deadline (mirrors `acceptance.rs::poll_until_match`). |
| R5 | `cli_help_lists_every_documented_flag` runs the binary, which means tests trigger a build of the binary — `cargo test -p varta-watch` does this automatically; no extra config needed. | Verify locally in §7 that `--help` exits 0. |
| R6 | `FileExporter` schema ambiguity for `Decode`/`Io` events. | Schema documented in §3 (`-` placeholder). Test asserts only line count; schema is rustdoc'd on `FileExporter`. |
| R7 | `Recovery` debounce per-pid means two distinct pids can each fire within the window. | Intentional and matches the contract ("once per stall within debounce"). Documented on `Recovery::on_stall`. |
| R8 | `Config::HELP` drift from actual flag handling. | One source of truth: the parser branches and the HELP string sit next to each other, with a unit test (`config_help_lists_every_known_flag`) inside `config.rs` mirroring `cli_smoke`'s assertion. (This unit test is additional and not part of the contract — keep it short.) |
| R9 | `recovery_cmd_fires_once_per_stall_within_debounce`'s "exactly once" check via `marker.exists()` is weak (touch is idempotent). | Strengthened by asserting `Spawned` then `Debounced` outcome ordering. The contract test only requires `marker exists exactly once`; a fresh tempfile that didn't exist prior + `Debounced` second outcome jointly imply this. |
| R10 | SIGINT handling without `libc`/`signal-hook` is not feasible in std-only. | Per D9, ship deadline-only shutdown. Tests use `--shutdown-after-secs`; static `AtomicBool` wired for future signal hook. Documented as open issue. |
| R11 | `clippy::print_stdout` forbid lint may bite when emitting `--help`. | Use `std::io::stdout().lock().write_all(...)` rather than `println!`/`print!`. Lint catches the macros only. |
| R12 | Multi-pid Prometheus output ordering not deterministic across HashMap. | Sort pids numerically before formatting. Tests use `contains()` so strictly speaking ordering doesn't matter, but stable output simplifies debugging. |
| R13 | Scope creep into Session 06's `varta-tests` end-to-end. | We touch only `crates/varta-watch/{src,tests}/**` and never create files under `crates/varta-tests/`. |
| R14 | `Box<dyn Exporter>` would allocate at startup, but we said no allocations in steady-state. | Steady state allocations are forbidden ON `varta-client::beat()`. Observer steady-state allocs are not contractually banned for v0.1.0; nonetheless we avoid `Box<dyn>` and use concrete `Option<...>` slots in `main` to keep it tidy. |
