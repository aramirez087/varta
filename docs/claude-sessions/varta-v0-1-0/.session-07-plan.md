## 3. Design Decisions and Rationale

### D1 — README code blocks are not cargo-tested; .rs examples are

`cargo test --doc` only tests `///` doc-comment blocks inside `.rs` source
files. Markdown code fences in README files are never compiled. The correct
posture is: (a) keep README code blocks accurate by hand, (b) put all
compile-verified runnable code in `crates/varta-client/examples/*.rs`.

The existing doctest in `client.rs:41` uses ` ```no_run ` — it compiles but
doesn't execute (no socket at test time). `cargo test --doc --workspace`
confirms nothing regressed.

### D2 — `[[example]]` sections required in Cargo.toml

Cargo only respects `required-features` when the example is declared
explicitly as `[[example]]`. Without the declaration, `cargo build --example
with_panic_handler` would silently build without the feature and produce a
compile error on the `install_panic_handler` symbol. Session 04's Cargo.toml
(verified by reading) contains no `[[example]]` sections — all three must be
added.

### D3 — Payload encoding in `with_payload.rs` uses bit-packing

The 64-bit payload is application-defined. The clearest demonstration is
packing two u32 fields:

```
high 32 bits  →  queue depth  (u32 cast to u64, shifted left 32)
low  32 bits  →  last error code (u32 cast to u64)
let payload = (queue_depth as u64) << 32 | (last_error_code as u64);
```

The observer carries `payload` opaquely, so this convention lives entirely in
the agent and any downstream tool that reads the exported metrics file.

### D4 — `docs/benchmarks/results.md` stub is created by Session 07

The root README must link to this file, and the link must not be a 404. Session
06 (e2e + bench harness) is not a DAG parent of Session 07, so the file does
not exist. A stub with a clear "populated by varta-bench" note satisfies the
link without inventing numbers.

### D5 — No `no_run` in example .rs files

Example files are built with `cargo build --example`, not run during CI. They
do not connect to a real socket during compilation, so the `Varta::connect`
call will be inside `fn main()` and will only fail at runtime (which is the
expected demo behavior). No special annotation needed.

### D6 — `basic.rs` uses `let _ =` to discard `BeatOutcome`

The minimal demo does not need to handle `Dropped`/`Failed`. Silently
discarding the result with `let _ =` is correct; `#[must_use]` is not on
`BeatOutcome` (verified by reading `client.rs`). If it were, the compiler
would warn, which `cargo build --examples` would surface.

### D7 — Cross-link topology

```
README.md
  └─→ crates/varta-vlp/README.md    ─→ docs/architecture/vlp-frame.md
  └─→ crates/varta-client/README.md ─→ crates/varta-vlp/README.md
  └─→ crates/varta-watch/README.md  ─→ docs/architecture/vlp-frame.md
                                    └─→ crates/varta-vlp/README.md
  └─→ docs/benchmarks/results.md
```

Every per-crate README links back to the workspace root at the top
("← [Workspace root](../../../README.md)") so readers arriving via crates.io
or GitHub directory browsing can navigate.

### D8 — No crates.io install snippet (path deps only)

The operator rules state: `path = "../<crate>"` for all inter-crate deps. The
README install section shows path-dep form and notes that a crates.io publish
is post-v0.1.0, matching the session brief exactly.

## 7. Example Skeletons (verified against public API)

### `basic.rs`

```rust
//! Minimal Varta beat loop — connect once, emit Status::Ok every 500 ms.
//!
//! Run alongside varta-watch:
//!   varta-watch --socket /tmp/varta.sock --threshold-ms 2000 &
//!   cargo run --example basic

fn main() -> std::io::Result<()> {
    let mut agent = varta_client::Varta::connect("/tmp/varta.sock")?;
    loop {
        let _ = agent.beat(varta_client::Status::Ok, 0);
        std::thread::sleep(std::time::Duration::from_millis(500));
    }
}
```

### `with_payload.rs`

```rust
//! Beat loop that packs queue depth and last error code into the 64-bit payload.
//!
//! Layout: high 32 bits = queue_depth, low 32 bits = last_error_code.
//! The observer carries the payload opaquely; decoding is an app concern.

use std::sync::atomic::{AtomicU32, Ordering};

static QUEUE_DEPTH: AtomicU32 = AtomicU32::new(0);
static LAST_ERROR: AtomicU32 = AtomicU32::new(0);

fn main() -> std::io::Result<()> {
    let mut agent = varta_client::Varta::connect("/tmp/varta.sock")?;
    loop {
        let depth = QUEUE_DEPTH.load(Ordering::Relaxed);
        let err   = LAST_ERROR.load(Ordering::Relaxed);
        let payload = (depth as u64) << 32 | (err as u64);
        let _ = agent.beat(varta_client::Status::Ok, payload);
        std::thread::sleep(std::time::Duration::from_millis(500));
    }
}
```

### `with_panic_handler.rs`

```rust
//! Demonstrates the opt-in panic handler.
//!
//! Build:  cargo build --example with_panic_handler --features panic-handler
//! Run:    cargo run  --example with_panic_handler --features panic-handler

fn main() -> std::io::Result<()> {
    // Register the hook before connecting so any early panic is still signalled.
    varta_client::install_panic_handler("/tmp/varta.sock");

    let mut agent = varta_client::Varta::connect("/tmp/varta.sock")?;
    for _ in 0..10 {
        let _ = agent.beat(varta_client::Status::Ok, 0);
        std::thread::sleep(std::time::Duration::from_millis(200));
    }
    Ok(())
}
```
