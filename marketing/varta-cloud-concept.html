01The market gap Varta sits in

Two crowded markets bracket the problem — and neither solves it. Varta owns the seam between them: process liveness + auto-recovery for fleets of long-running local agents.

⏰

Cron / heartbeat monitors

healthchecks.io, Cronitor, Dead Man's Snitch, Better Stack. Built for "did this job check in over HTTP." Coarse (per-minute pings), one URL per check, no recovery, no sub-second detection, nothing for thousands of co-located PIDs.

🐺

Varta — the missing layer

Sub-µs heartbeats, one observer per host watching thousands of agents, stall detection at the ms, automatic recovery, cryptographic attestation, and safety-critical build profiles. The "is my agent actually alive — and fix it if not" layer.

🧠

AI agent observability

Langfuse, AgentOps, Braintrust, Arize. Built for LLM traces, evals, and token cost — the quality of an agent's reasoning. They assume the process is up. None of them tell you the agent wedged and stopped beating.

The timing thesis. AI agents are turning into long-running background processes, not request/response calls. As autonomous agents, robots, and edge devices proliferate, "my agent silently hung and I found out from a customer ticket" becomes a top-tier failure mode — and the trace/eval tools are blind to it. Varta already speaks that language: "Your background workers die silently — find out before your users do."

02The product: open-core

Keep the protocol and observer 100% open — that's the adoption engine. Sell the cloud control plane that a growing fleet eventually needs.

🟢 Open source  free forever

  • VLP protocol + 6 language clients (Rust, Py, Go, Node, .NET, JVM)
  • varta-watch observer — stall detection, recovery, Prometheus /metrics
  • Self-hosted, unlimited agents, zero telemetry leaves the box
  • Drives bottom-up developer adoption + credibility

🟠 Varta Cloud  paid

  • Observers stream telemetry up via a lightweight, outbound-only agent
  • Multi-fleet dashboards — every host, every agent, one pane
  • On-call — PagerDuty / Opsgenie / Slack / webhook routing + escalation
  • Recovery audit trail — who/what/when restarted, tamper-evident
  • Anomaly detection + historical analytics + SLA / uptime reports
  • RBAC / SSO / SAML, retention tiers, multi-tenant org management

Recovery never depends on the cloud — the observer is autonomous. The cloud adds visibility, coordination, and evidence. That's the trust story.

03Who buys this

Rank by willingness-to-pay = (cost of a silent stall) × (number of agents). The safety-critical segments are already coded into Varta's Class-A build profiles — a moat.

🤖 AI agent platforms

Teams running long-lived autonomous agents / workers. A hung agent = stuck workflows, burned spend, silent SLA breach. Fast-growing, well-funded, OSS-native buyers.

🦾 Robotics & autonomous systems

Drones, AMRs, self-driving rigs. Many co-located daemons per machine; a wedged process is a safety event. Sub-µs + recovery is non-negotiable.

🩺 Medical / clinical edge

Varta already ships Class-A safety profiles & STRIDE threat model. IEC 62304 / FDA evidence is a budget line, not a nice-to-have.

🏭 Industrial IoT & edge fleets

Thousands of gateways running data-collection daemons in the field; remote, intermittent connectivity. Outbound-only uplink fits.

📈 Fintech / trading infra

Low-latency market-data and execution daemons where a stalled process is measured in lost dollars per second.

🧩 Platform / infra teams

Anyone running a fleet of background workers who's outgrown "a cron monitor and hope," but doesn't want a pod + HTTP port per PID.

06Business model & GTM

The open-core motion

  • Top of funnel: OSS install (`curl | sh`, crates.io, PyPI, npm). Devs adopt for free, in their own infra.
  • Activation: fleet grows past 1 host → "I need one dashboard for all of these" → Cloud signup.
  • Expansion: more agents, more fleets, longer retention → tier upgrades (usage-based).
  • Enterprise: regulated buyer needs the compliance/audit pack + on-prem → sales-assisted.

Why this is defensible

  • Protocol lock-in via openness — VLP becomes the standard; clients in 6 languages already.
  • Engineering moat — zero-dep, no_std, sub-µs, AEAD, Class-A profiles are hard to copy.
  • Compliance moat — threat model + safety profiles are years of work a competitor can't bolt on.
  • Wedge position — neither cron-monitors nor trace tools want to rebuild low-level liveness.

07What to do next — 90 days to first paying user

You already have the hard part (the OSS protocol + observer + clients). The SaaS is a thin, trustworthy cloud on top. Sequence it for the fastest validated dollar.

Weeks 1–3 · Validate

  • Interview 10 target users (AI-agent + robotics + edge teams) running fleets today.
  • Confirm the pain & willingness-to-pay; pick 3 design partners.
  • Add a one-line "Varta Cloud — join waitlist" CTA to varta.sh + README.
  • Instrument OSS install telemetry (opt-in) to size the funnel.

Weeks 4–9 · Thin cloud MVP

  • Build the outbound uplink in varta-watch (batched, attested, opt-in).
  • Ship the smallest valuable cloud: multi-host dashboard + Slack/PagerDuty alert.
  • Stripe billing, single Pro tier, manual onboarding for the 3 partners.
  • Recovery audit log (you already have tamper-evident audit primitives).

Weeks 10–13 · Monetize

  • Convert ≥1 design partner to paid; write the case study.
  • Open public self-serve signup; turn on Team tier.
  • Scope the Enterprise compliance pack (Class-A evidence) for first regulated lead.
  • Decide: bootstrap on OSS goodwill vs. raise on the agent-infra thesis.
Cheapest possible first test (this week): publish this page (or a landing variant) at varta.sh/cloud with a waitlist form. If your existing OSS audience signs up, you've validated demand before writing a line of cloud code. The OSS repo is your distribution — use it.

Key risks to retire early

Low conversion. Open-core converts at 1–5%. Mitigate: make the cloud genuinely painful-to-rebuild (alerting, multi-fleet, compliance), not a thin wrapper over /metrics.

"Just use Prometheus + Grafana." You already ship that bundle free. The cloud must sell time-saved + on-call + audit + compliance, not dashboards alone.

Trust / data residency. Edge & medical buyers fear telemetry leaving the box. Lead with outbound-only, opt-in, on-prem option, and "recovery never needs the cloud."

Solo maintainer bandwidth. A SaaS needs uptime + support. Consider a managed-Postgres + serverless stack to keep ops near-zero; or partner/raise before committing.
