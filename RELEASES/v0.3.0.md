# v0.3.0 — Cross-Client Safety Hardening

Varta v0.3.0 collects the post-0.2 hardening work across `varta-watch`, the Rust crates, and the official clients. The release tightens shutdown/reconnect behavior, secure-UDP nonce handling, panic/terminal-frame ordering, bounded observer work, and release/deployment packaging.

## Highlights

- Rust crates `varta-vlp`, `varta-client`, and `varta-watch` are versioned at `0.3.0`.
- `varta-watch` keeps the deployment surface from v0.2.0 and adds the accumulated safety fixes documented in `CHANGELOG.md`.
- Official clients are ready for their ecosystem tags: Node `0.3.0`; Python, Go, Java, and .NET `0.2.0`.
- Secure-UDP clients refresh session state before terminal nonce exhaustion and preserve commit-on-success semantics around wrap boundaries.
- Closed/disposed agents now fail closed consistently instead of reconnecting, sending, or throwing from normal beat paths.
- Panic/terminal emitters use process-wide monotonic ordering so genuine later terminal frames are not rejected as stale replays.

## Breaking changes

- Rust `BeatOutcome::Dropped` carries a `DropReason` payload.
- `varta-watch` enables default-on UDS rate limiting and isolates recovery child environments by default.
- Shell-mode recovery is removed; migrate `--recovery-cmd` usage to `--recovery-exec`.
- `varta_rate_limited_total` is labelled by reason.
